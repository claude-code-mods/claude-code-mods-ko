# Just Do It

> 한국어판은 claude-code-mods-ko 프로젝트가 번역했습니다. 원작자와 라이선스는 문서 끝에 있으며, 영어 원문은 [README.en.md](README.en.md)에서 볼 수 있습니다.

옵트인 방식의 이어가기 플러그인입니다. 네이티브 Python 명령 훅이 세션 캐시를 유지하고, 모듈이 그 캐시를 보여 주며 일시정지, 재개, 유지보수, 자문 감사를 제공합니다. 작업 기록은 Linear에 남습니다. 이 캐시는 결코 권한을 부여하지 않습니다.

## 증거와 전달

행동 요청에서는 DoD, 담당자, 실제 이슈 식별자로 결과를 선언하세요. 성공 영수증, 명시적 검사, 입력한 트랜스크립트/파일 포인터가 증거 색인을 이룹니다. 메타데이터 영수증은 결과를 입증할 수 없습니다. 의존성 검사는 전이적입니다. 파일, 증거 또는 세대가 바뀌면 다시 검사해야 합니다.

`deliver`는 제안된 최종 텍스트와 결과 id를 정확히 기록합니다. Stop은 그 해시를 실제 최종 어시스턴트 메시지와 비교하고 전달과 관련된 모든 결과를 확인합니다. 누락, 공백, 불일치, 불완전한 전달은 미해결로 남습니다. 증거와 전달이 일치하면 `delivered; semantic review pending`이 됩니다.

**현재 어떤 경로도 독립적인 의미적 완료를 보증하지 않습니다.** `audit-record`는 구현 에이전트가 호출할 수 있으므로 그 판정, 출처 필드, `ADEQUAAT`로 시작하는 텍스트조차 독립성을 입증할 수 없습니다. `/just-do-it audit`는 호스트에 문서화된 `model.fork`를 한 번 호출하고 자문 텔레메트리만 기록합니다. HIATEN, ONZEKER, 공백/오류, 긍정적 자문 회신 모두 의미적 검증을 미해결로 둡니다. 해시는 바이트를 묶을 뿐 정확성을 입증하지 않습니다. 현재 완료 경로는 승인됨/검증됨 라벨을 내보내지 않습니다.

브리지 명령은 `python3 -I <plugin>/hooks/bridge.py ACTION --session SESSION_ID`를 사용합니다. JSON 액션은 표준 입력을 읽으며 현재 세대를 사용하세요. 의도적으로 낙관적 동시성을 쓰는 경우가 아니면 revision을 생략하세요.

- `contract`: `{"generation":1,"issue":"TEAM-1","outcomes":[{"id":"result","owner":"session","dod":"Required effect","dependencies":[]}]}`.
- `evidence`: `{"generation":1,"id":"result","receipt":"actual-id","pointer":{"type":"transcript","tool":"Bash","tool_use_id":"actual-id","outputHash":"actual-hash"},"inspection":"What the output establishes"}`. 파일 포인터에는 실제 Read 영수증과 현재 파일 해시가 필요합니다.
- `deliver`: `{"generation":1,"text":"Exact final text","outcomes":["result"]}`.
- `reconcile`: `{"generation":2,"items":[{"id":"result","disposition":"retain"}]}`. 현재 세대라도 한 배치에서 미해결 `needsReconciliation` 결과를 모두 다루세요. `contract`는 새 결과만 선언하거나 기존 계약을 세대 변경 없이 반복합니다. 기존 계약 변경에는 권한 있는 `reconcile`이 필요합니다. 대기 목록에는 조정이 필요한 담당 작업이 남습니다. `?`로 끝나는 질문은 그 작업이 `next`와 대기 목록에 보인 상태로 답할 수 있습니다. 지원되는 처리 방식은 `retain`, `amend`, `add`, `pause`, `cancel`, `supersede`입니다. 모든 항목은 관측된 UserPromptSubmit 세대와 전체 프롬프트 해시에 묶입니다. 범위 변경은 유지된 프롬프트 첫 2000자 안의 정확한 인용도 필요합니다. 알 수 없는 레거시 프롬프트 출처는 조정을 권한 부여할 수 없습니다. `amend`에는 새 `dod`가, `add`에는 새 id, `dod`, `owner`, 그리고 `[A-Z][A-Z0-9]+-\d+`와 일치하는 최상위 `issue`(`contract`와 같은 구문 검사기) 또는 그 검사를 통과한 기존 결과를 지정하는 최상위 `inheritIssueFrom`이 필요합니다. 예: `{"generation":2,"inheritIssueFrom":"result","items":[{"id":"result","disposition":"retain"},{"id":"extra","disposition":"add","quote":"add extra","dod":"Extra effect","owner":"session"}]}`. 이슈와 상속은 함께 쓸 수 없으며, null과 임의 식별자는 원자적으로 거부됩니다. 구문 검증은 Linear에서 이슈를 확인하지 않습니다. `supersede`에는 다른 기존 결과나 배치에서 추가된 `replacement`가 필요합니다. 기존 담당, 영수증, 계약, 처리 기록은 유지됩니다. pause/cancel/supersede는 완료를 선언하지 않고 기존 결과를 중단합니다. 인용은 출처를 연결할 뿐 의미 해석에는 검토가 필요합니다. 계약과 조정 캐시 편집은 커밋 전에 트랜잭션 방식으로 검증됩니다.
- 선택 사항인 계약 `criteria`: `[{"id":"bytes","kind":"file-sha256","path":"/absolute/result","sha256":"<64 lowercase hex characters>"}]`. generation/id와 함께 `check-outcome`은 각 기준을 현재 기준 해시 및 세대에 기록합니다. Stop은 링크를 따르지 않는 제한된 디렉터리 순회로 정확한 바이트를 다시 확인합니다. `{"id":"meaning","kind":"semantic"}`은 명시적으로 미해결 상태입니다. 명령을 포함한 알 수 없는 종류는 거부됩니다. 이 검사에는 일반적인 검사된 증거도 필요하며 바이트 일치가 의미적 승인을 보증하지 않습니다. 기준이 없는 결과는 증거만 있고 의미적으로 미해결입니다.
- `wait`/`release-wait`: 구체적으로 관측된 선행 조건 포인터, 현재 세대, 컬렉션/id. 대기는 의존 작업으로 전파되고 독립 작업은 계속됩니다. 해제가 권한을 부여하지는 않습니다.

일시정지, 중단, 승인 거부, 네이티브 루프 상한이 우선합니다. 같은 작업 요청이 반복되면 진단과 실제 트랜스크립트에 묶인 불완전 인계를 요구합니다. 재귀 Claude 프로세스, 타이머, 데몬, cron은 만들지 않습니다. 단순 질문에는 인위적인 계약이 필요 없습니다. 중단된 결과는 조용히 완료되지 않고 미해결로 남습니다.

## 네이티브 프롬프트 출처

로컬 2.1.312 타입은 네이티브 봉투를 BaseHookInput과 `hook_event_name: UserPromptSubmit`, `prompt: string`, 선택 사항인 `source: user|sdk|system|loop_wakeup|schedule_wakeup|poll_event`, 선택 사항인 `session_title`로 문서화합니다. `source=user`는 대화형 입력창으로 설명됩니다. 이 직렬화된 필드는 임의의 브리지 CLI 호출을 인증하지 않습니다. 모든 직렬화된 프롬프트 콜백은 `source=user`, `origin=composer`, `authenticated=true`를 주장하는 콜백까지 포함해 의도, 세대, 증거, 대기를 그대로 보존합니다. `lastPromptSource.authenticated`는 항상 false입니다. 보호된 모듈-Python 권한 전달 수단이 없으므로 `reconcile`은 레거시 캐시된 사용자 출처도 거부합니다.

묶이지 않은 모든 네이티브 `UserPromptSubmit`은 누락·알 수 없음·시스템·피어·사용자 주장 여부와 상관없이 별도의 `observationRevision`을 진행시키고 `promptBindingPending`을 설정합니다. 이는 새로운 사용자 권한이 아니라 관측 장벽입니다. 의도, 세대, 담당 계약, 증거/기록, 영수증 검사 기록, 유효한 대기는 유지됩니다. 증거 검사와 기계적 확인은 리비전에 묶이므로 이전 검증은 오래된 것이 되고, 감사 텔레메트리는 오래된 것으로 표시되며 이전 관측의 전달 후보는 인식할 수 없습니다. 새로운 CLI 검사/확인/전달 기록은 현재 관측 리비전을 사용하지만 미해결 바인딩을 지우지는 못합니다. CLI 권한 플래그나 초기화 동작은 노출되지 않으며, 일시정지/재개도 지우지 않습니다. 완료 인식을 재개하려면 지원되는 보호된 호스트 전달이 필요합니다. Stop은 유효한 선행 조건/백그라운드 대기, 일반 대화, 상태 질문에는 여전히 양보할 수 있습니다. 그런 양보는 전달을 주장하지 않습니다. 상태 응답은 미해결 담당 작업을 유지합니다. 그 밖의 묶이지 않은 작업은 기존 루프 상한이나 트랜스크립트 인계를 통해 불완전으로 양보합니다. 반복 관측은 호스트 이벤트 id가 없는 동일 텍스트도 각각 장벽을 만들며, 기존 이벤트 id 중복 제거는 변경되지 않습니다. 레거시 캐시는 리비전 0으로 추가 마이그레이션되며 새로운 바인딩 주장은 없습니다.

모듈은 문서화된 `prompt.submit`만 관측하며 엔진이 고정한 `origin`과 `isMeta`를 세션 원자에 유지합니다. 관측은 세션, 현재 캐시된 세대, 로컬 시퀀스, 정확한 텍스트의 SHA-256, 선택적인 실행 중 턴 id에 묶입니다. 호스트는 PromptSubmitInput에 메시지 id를 제공하지 않으므로 `observationId`는 호스트 메시지 id가 아니라 명시적으로 로컬 바인딩입니다. 비메타 입력창 출처만 로컬에서 사람으로 분류됩니다. 어떤 관측도 권한으로 CLI에 직렬화되지 않습니다. 항상 `next(e)`를 변경 없이 호출합니다. 타입에 따르면 next는 하위 모듈 훅, 네이티브 UserPromptSubmit 설정 훅을 실행한 뒤 프롬프트로 진입합니다. 이 훅을 건너뛰는 정책은 관측을 남기지 않으며, 다른 이벤트로 우회하지 않습니다. 관측/해시 실패에도 프롬프트는 변경 없이 전달됩니다. 이는 호스트 로컬 관측이지 완료된 네이티브 권한 배선이 아닙니다. 기존의 명시적 모듈 일시정지/재개 제어는 별개입니다. Python을 통한 완전한 사람 의도 갱신과 범위 조정은 지원되는 보호된 인계가 없어 여전히 불가능합니다.

## 장애 출처

새로 실패한 도구 콜백마다 정확한 영수증 id, 세대, inputHash, outputHash에 연결된 장애가 생깁니다. 동일한 중복 콜백은 성공/실패 콜백 이름에 걸쳐 아무 동작도 하지 않습니다. 충돌하는 콜백 페이로드는 원래 영수증을 유지하고 출처 충돌 장애를 엽니다. 명령/출력 바이트가 반복되어도 각 호출은 자체 장애를 가집니다.

빈 실패 출력과 시간 초과는 `effect: unknown`으로 시작합니다. 쓰기를 재시도하거나 면제를 요청하기 전에 원인을 살펴보고 실제 효과를 다시 읽으세요. `waive-incident`에는 기존의 검사된 로컬 증거, 허용된 분류, 실질적인 메모, 정확한 포인터, 명시적 효과(`not-started`, `confirmed-no-effect`, `effect-confirmed` 중 하나)가 필요합니다. 이는 증거 연결이 있는 에이전트 주장이지 독립적으로 검증된 의미적 사실이 아닙니다. `resolve-incident`에는 소유 플러그인 소스/백업 해시, 현재 Read 영수증, 검증, 롤백 기록이 추가로 필요합니다.

연결된 실패 콜백 영수증이 없었던 도구 실패 장애(`status`의 `sourceGaps`)는 검사하거나 면제할 수 없습니다. `mark-untraceable`(`{generation, ids, note}`; 고유 id 또는 8자 이상의 접두사; 20자 이상의 메모; 전부 또는 전무)은 그 장애에 `provenance.state = untraceable`을 기록합니다. 이는 주석일 뿐으로 장애는 미해결로 남고 `waive-incident`와 `resolve-incident`는 여전히 거부하며 Stop도 완화되지 않습니다. 그러면 `status`가 `sourceGaps` 대신 `untraceableIncidents`에 나열합니다.

정확한 sourceReceipt가 없는 레거시 미해결 도구 장애는 변경되지 않으며 허위 재구성으로 면제·해결할 수 없습니다. 출처 공백은 미해결 진단 의무입니다. 종료된 기록은 보존됩니다.

## 유지보수

SessionStart는 결정론적인 자체 플러그인 어댑터를 실행합니다. 지정된 자체 스크립트, 매니페스트, 훅 설정, 모듈, 상태 타입에 대한 성공한 Write/Edit 콜백은 재검사를 트리거하고, 정확히 그 경로에 대한 실패한 Read/Write/Edit 콜백도 진단을 트리거합니다. 다른 실패는 수리 권한을 주지 않습니다. 해시/모드 서명에는 누락된 파일이 포함되고, 실패 지문에는 콜백 id가 제외되어 같은 실패가 중복 제거됩니다. 30초 최소 간격은 작업을 다음 관련 이벤트나 프롬프트로 큐에 넣으며, 변경 없는 검사는 5분간 중복 제거됩니다. 타이머나 데몬이 없어 큐 작업은 다른 이벤트를 기다립니다. 일시정지/중단이 우선합니다. 자동 진단은 선언 대상 파일 시스템 접근 전마다 명시적 허용 목록을 확인합니다. 자체 스크립트 세 개, 매니페스트, 훅 설정, `hooks/register.tsx`, `types/index.d.ts`입니다. 절대 경로·순회·알 수 없거나 잘못된 선언은 대상 탐색 없이 발견 사항을 만듭니다. 서명, 매니페스트 확인, SessionStart 탐색, 진단, 검증, 수리 사전 검사를 포함한 모든 자동 설정 읽기는 기존의 디렉터리 fd 기반 no-follow 판독기를 사용하며 사용자 정의 심볼릭 링크 조상과 리프를 거부합니다. 자동 스크립트 수리는 소스 및 보관 설명자를 고정하고 설명자 chmod를 사용하며, 검증 롤백은 같은 제한된 판독기를 사용합니다. 수동 수리와 일반 증거 해시는 별도 동작을 유지합니다. 자동 진단은 PATH를 검색하지 않으며, 수동의 더 넓은 진단은 문서화된 설정/설치 경로/PATH 범위를 유지합니다. 진단은 이름이 지정된 플러그인 파일로 제한되고, 수리에는 `just-do-it` 매니페스트가 필요하며 이름이 지정된 자체 스크립트에 대해 최대 세 번의 소유자 실행 비트 수리를 수행합니다. 각 수리는 `apply_fix`, 백업/해시 검증, 충돌 인식 롤백을 재사용합니다. HOME/설정/비밀 검사는 자동으로 실행되지 않습니다. 상태 보관은 나이만으로 결과 완료를 증명할 수 없으므로 수동 유지보수 작업으로 남습니다.

`/just-do-it maintain`은 이름이 지정된 플러그인 파일과 기존 설정 및 설치된 플러그인 기록의 훅/설치 경로 부분을 읽습니다. `maintain record`는 높음/보통 발견 사항을 기록하고, `maintain fix`는 기존의 명시적으로 안전한 자체 플러그인 수리만 적용합니다. 알 수 없는 옵션은 읽기 전용으로 남습니다. 외부 설정/훅/플러그인 발견 사항은 제안일 뿐입니다. 가드, 권한, 라우팅, 다른 플러그인, 인증, 자격 증명은 절대 변경하지 않습니다.

외부 진단 어댑터는 미해결입니다. 설치된 `hook-doctor` 스킬은 읽기 전용 진단 `node <hook-doctor>/bin/doctor.mjs <project> --json`(네트워크·쓰기 없음)을 문서화하지만 사용자 설정과 참조 스크립트도 읽습니다. 자동으로 호출되지 않습니다. 브리지의 폐쇄된 로컬 전용 가져오기/프로세스 계약은 하위 프로세스 경로를 허용하지 않으며, 외부 어댑터에는 별도로 제한된 호스트 측 통합이 필요합니다. 그 발견 사항에서 광범위한 수리 권한을 추론하지 않습니다. Python 훅이 시작되기 전 실패, Bash 기반 설정 쓰기, 정확히 이름이 지정된 파일 밖의 변경, 이후 일치하는 이벤트가 없는 외부 편집은 자동으로 관측되지 않습니다. `maintenance.coverage` 필드가 이 제한된 어댑터 범위를 명시합니다. 소유권은 매니페스트와 파일 소유권으로 로컬에서 확인됩니다. 이는 함대 임대나 배타적 기록자 증명이 아닙니다. 설치와 유지보수는 다른 플러그인 기록자가 유휴 상태에서 실행하세요.

## 패널

패널은 세션 시작, 턴 완료, 명령, 수동 새로고침 시 권위 있는 브리지 상태를 읽습니다. 개별 결과의 기준/증거 수, 단계, 다음 동작, 마지막 성공 새로고침을 나열합니다. 읽기 실패는 유지된 스냅샷을 오래된 것으로 명시적으로 표시합니다. 폴링하지 않으며 외부에서 만든 변경은 다음 새로고침에 보입니다. 횟수는 범위나 완료를 입증하지 않습니다.

## 설치 프로그램 안전

`../install.sh install|update|uninstall`은 기본 사용자 범위 플러그인 CLI를 사용합니다. `.ops-jdi-owner.json`이 없는 기존 마켓플레이스는 거부됩니다. 레거시 설치를 위해 표시자를 만들지 마세요. 알 수 없는 파일/런타임은 충돌 검사, 비공개 백업, 충돌 인식 롤백과 함께 보존됩니다. `rollback <backup>`에는 일치하는 소유 설치가 필요합니다. 이 후보에 대해 실제 설치 프로그램을 실행하지 않았습니다.

`install.py`는 읽기 전용 `runtime_manifest(root)`와 `compare_runtime(source,target)`를 제공합니다. 명시적으로 이름이 지정된 매니페스트, 훅, 브리지/모듈, 플러그인 상태 타입만 런타임 해시 맵에 들어갑니다. 생성된 호스트 선언, 테스트, 런타임, 알 수 없는 파일은 제외됩니다. 비교는 소유권을 가져오거나 동기화를 권한 부여하지 않습니다. 기존 설치 프로그램의 변경 동작은 별도입니다.

## 선택적 함대 검사

매니페스트는 선택 사항인 `userConfig.fleetConfigPath`(파일, 기본값 비어 있음)를 선언합니다.

네이티브 모듈 목록은 핵심 모듈 뒤에 `fleet-entry.ts`를 추가하고 모든 명령 훅을 유지합니다. 경로가 없거나 비어 있으면 함대 검사가 꺼집니다. 명시적인 절대 경로의 비공개 설정은 검사를 켜고 세션 소유 60초 타이머가 시작되기 전에 0이 아닌 지속적인 판단 허용량을 공급해야 합니다. 켜진 검사는 호스트 모델을 호출할 수 있습니다. 이 오프라인 통합에서는 모델 호출이 없었습니다. 세션 종료와 잘못되거나 비활성화된 설정은 타이머를 취소합니다. 출처 범위와 설정 필드는 [함대 계약](docs/fleet-guard.md)을 참고하세요.

함대 판단은 자문입니다. 큐에 넣은 자문은 실행, 효과 영수증, 권한, 완료가 아닙니다. 네이티브 소스 안전 공백이 현재 자문 전송을 막고 있습니다. 보호된 호스트-네이티브 출처 전달이 여전히 미해결입니다. 로컬 사람 트랜스크립트 관측은 `promptBindingPending`을 지우거나, 브리지 조정을 권한 부여하거나, 독립적인 브리지 수락을 설정하지 않습니다. 보편적 완료 보증이나 실제 런타임 수용 주장은 없습니다.

런타임 해시 매니페스트에는 핵심 파일과 함께 `fleet_guard.py`, `fleet.ts`, `fleet-source.py`, `fleet-runtime.ts`, `fleet-entry.ts`가 포함됩니다. 기존 설치 프로그램의 백업, 충돌, 소유권, 런타임, 알 수 없는 파일 보존 규칙이 적용되며 소유권 없는 현재 마켓플레이스는 여전히 거부되어야 합니다.

## 검사와 한계

`rb status` 이후 기존 리소스 승인 경로를 통해 실행하세요.

```
python3 -I -m unittest discover -s <plugin> -p 'test*.py'
python3 -I -m unittest discover -s <skill> -p 'test_install.py' -v
python3 -I -m unittest discover -s <skill> -p 'test_manifest.py' -v
tsc -p <plugin> --noEmit
claude plugin test <plugin>
claude plugin validate <plugin>
python3 -I <plugin>/repair_fixture.py
```

트랜스크립트 메시지 스캔에는 POSIX 디렉터리 fd `open`/`stat`, no-follow `stat`, `O_DIRECTORY`, `O_NOFOLLOW`, `O_NONBLOCK`이 필요합니다. 지원되지 않는 플랫폼은 미해결 인계와 함께 닫힙니다(fail closed). 모든 디렉터리는 링크를 따르지 않고 보유한 부모 디스크립터에 상대적으로 열립니다. 리프 소유권/유형과 전후 동일성, 디렉터리 간선이 수락 전에 확인됩니다. macOS에서는 루트 소유의 정확한 시스템 링크 `/var -> private/var`, `/tmp -> private/tmp`, `/etc -> private/etc`만 확장 후 재확인하며, 그 `/private/...` 대상도 같은 no-follow 순회를 거칩니다. 사용자 정의 심볼릭 링크 조상과 리프는 거부됩니다. 스캔 중 관측된 동시 변경은 미해결로 남습니다. 이는 관측 시점 검사이지 파일 시스템 잠금이나 의미적 인증이 아닙니다. 한계는 전체 128MB, 레코드당 1MB, 5초이며 일반 파일 증거에는 별도의 16MB 한계가 있습니다.

테스트는 임시 픽스처와 호스트 목을 사용하며 실제 설치 세션이 아닙니다. 로컬 Stop 스크립트에는 네트워크/모델/하위 프로세스 경로가 없습니다. 타이밍 검사는 로컬 지연을 측정하며 청구가 아닙니다. `/just-do-it audit`만 명시적 모델 호출이며 일반 Stop은 호출하지 않습니다. 이 명령들이 유료 증명을 권한 부여하지 않습니다.

`smoke.py`에는 `--run-paid-smoke`와 구체적인 `--max-budget-usd`가 모두 필요합니다. 명시적 옵트인이 없으면 아무것도 지불하지 않습니다. 구조적 기대값은 의미 검토 미해결 상태의 전달이며 독립 수락이 아닙니다. 새로 승인된 예산 없이 유료 스모크를 실행하지 마세요.

미완료: 진정한 독립적 의미 검토 출처, 정확한 파일 바이트를 넘어선 DoD별 완전한 타입 의미 검증, 외부 유지보수 어댑터와 호스트 훅 시작 실패 관측, 실제 패널/네이티브 세션/설치 수용, 유료 런타임 비용 증명. 캐시 트랜잭션은 파일 시스템 수리를 원자적으로 만들지 않으며 기존 수리 롤백이 별도로 처리합니다. 프롬프트 해시는 관측된 콜백 연결을 설정할 뿐 호스트 인증 사용자 신원은 아닙니다. 자동 출처 완전성과 실제 사용자 의미는 여전히 검토 의무입니다. 오프라인 테스트는 이 요구 사항을 종결하지 않습니다. 최종 후보는 별도의 독립 검토가 필요합니다.
