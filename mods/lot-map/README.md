# Claude Code용 Lot Map

> 한국어판은 claude-code-mods-ko 프로젝트가 번역했습니다. 원작자와 라이선스는 문서 끝에 있으며, 영어 원문은 [README.en.md](README.en.md)에서 볼 수 있습니다.

`lot-map`은 Claude Code용 모드입니다. 채팅 옆 패널에 작업의 실시간 지도를 보여 줍니다. 모든 도구 호출, 모델 단계, 훅, 스킬이 중심에서 자기 역으로 맥박을 보내므로 명령 목록을 읽는 대신 메모리, 파일, 셸, 웹, 에이전트가 작동하는 것을 볼 수 있습니다.

이 모드는 사용자의 컴퓨터에서 실행되고 어디로도 아무것도 보내지 않습니다. 로컬이라고 해서 눈이 막힌 것은 아닙니다. 도구 호출을 추적하는 다른 모드처럼 각 호출 전체를 전달받고, 그곳에서 이름만 가져갑니다. [읽고 보관하는 것](PRIVACY.md)과 [그것을 지키는 검사](PRINCIPLES.md)를 참고하세요.

![작업 세션 중의 지도](docs/demo.gif)

*모드 자체 그리기 코드로 재생한 가상의 세션입니다. [비디오(MP4)](docs/demo.mp4), 또는 [브라우저에서 재생](https://alexeyw.github.io/lot-map/)할 수 있습니다. 그 페이지는 같은 코드를 실행하며 각 호출이 모드에 전달하는 것과 모드가 보관하는 것을 보여 줍니다.*

## 설치

터미널 세션의 프롬프트에서:

```
/plugin install lot-map --marketplace alexeyw/lot-map
```

마켓플레이스 추가에 `y`로 답한 뒤 범위를 선택하세요. 셸에서는:

```bash
claude plugin install lot-map --marketplace alexeyw/lot-map
```

어떤 마켓플레이스에도 플러그인이 없다고 나오면 먼저 마켓플레이스를 추가하세요.

```bash
claude plugin marketplace add alexeyw/lot-map
claude plugin install lot-map@lot-map
```

데스크톱 앱에서는 프롬프트 상자 옆의 **+**, **Plugins**, **Add marketplace**에 `alexeyw/lot-map`을 입력하고 **Add plugin**을 누르세요.

패널은 세션이 시작되면 자동으로 열립니다. `openAtStart`가 꺼져 있으면 `/lot-map`을 기다립니다. 터미널에서는 최소 144열이 필요하며, 그렇지 않으면 `/lot-map`을 입력하세요. 또 그림을 요청하지 않는 한 텍스트만 그립니다. 그림이나 브라일 점으로 보는 방법은 [터미널에서](#in-a-terminal)를 참고하세요. macOS의 Claude Code 2.1.321에서 만들고 테스트했으며, Windows와 Linux에서도 동작한다는 보고가 있습니다.

Team·Enterprise 로그인에서는 트랜스크립트에 `lot-map: its classic.PreToolUse hook was skipped` 같은 알림이 나올 수 있습니다. `guardedHooks`를 끄면 사라지며, 그때 지도가 잃는 것은 [표시 내용](#what-it-shows)에 나와 있습니다.

한국어 마켓플레이스에서는 다음 명령으로 설치합니다.

```
/plugin install lot-map@claude-code-mods-ko
```

## 업데이트

셸에서:

```bash
claude plugin marketplace update lot-map
claude plugin update lot-map@lot-map
```

그다음 세션에서 `/reload-plugins`을 실행하세요. 이미 설치된 마켓플레이스가 여러 개라면 `claude plugin marketplace list`로 이름을 확인하세요.

## 무엇이 켜지는가

| 역 | 시점 |
| --- | --- |
| You | 사용자의 메시지, 질문, 전달된 파일, 작업 목록, 계획, 승인 요청 |
| Model | 각 모델 요청, 컨텍스트 압축 |
| Memory | Claude Code의 메모리 폴더와 옵션에서 지정한 것 |
| Files | Read, Write, Edit, Grep, Glob, 언어 서버의 코드 인텔리전스, 파일만 다루는 셸 명령(`cat`, `grep`, `mv`, `rm`, `sed`, `tee`, `find … -delete` 등 읽기·검색·이동·삭제·편집) |
| Shell | 그 밖의 모든 셸 명령 |
| Network | 웹 가져오기·검색, MCP 서버, claude.ai에서 유지되는 작업(아티팩트, 프로젝트, 디자인), 네트워크에 닿는 것이 알려진 셸 명령(`curl`, `gh`, `ssh`, `rsync`, `git push`, `npm install`, `docker pull` 등), `$(…)` 안에서도 같음 |
| Browser | 브라우저 도구 |
| Agents | 서브에이전트, 워크플로, 일정, 백그라운드 작업 대기. 그들의 호출은 이 역에서 시작 |
| Skills | 스킬, 도구 검색, 스킬·플러그인·커넥터 카탈로그 |
| Hooks | 호출을 거부하거나 권한을 묻거나 컨텍스트를 추가하거나 잠깐 멈추는 설정 훅 |

Windows에서는 PowerShell 도구를 Bash와 같은 방식으로 읽되 PowerShell 이름을 씁니다. `Get-Content`, `Select-String`은 Files, `Invoke-WebRequest`는 Network를 켭니다. 전체 경로로 실행된 프로그램은 공백이 있는 따옴표 경로에서도 이름으로 읽고, `CURL.EXE`는 `curl`입니다.

셸 역은 명령의 이름을 기준으로 하며 실제 동작은 보지 않습니다. 연결을 여는 스크립트(`python -c "…"`)는 Shell로 표시됩니다. `sudo`, `env`, `timeout`, `nohup`, `xargs` 뒤의 명령은 실제로 실행되는 명령으로 읽고, `find … -exec`는실행되도록 지정된 명령으로 읽습니다. 반복문이나 조건문(`for … do`, `if … then`, `while`, `!`, `{ … }`) 안의 명령과 셸이나 `eval`에 넘기는 줄(`bash -c "…"`)도 같습니다. here-document의 텍스트는 읽지 않으므로 그 안에 기록하는 파일은 내용과 무관하게 Files로 표시됩니다. 한 줄은 처음 8,000자까지만 읽습니다. `npx`는 `-y`가 있을 때만 Network로 셉니다. 없으면 이미 설치된 것을 실행하는 경우가 많기 때문입니다.

무언가 시작하면 맥박이 나가고 끝나면 돌아옵니다. 거부와 오류는 빨간색이 됩니다.

## 지도 읽기

- **경로.** 메인 루프가 지나온 최근 역들을 순서대로 가는 가는 선이있고, 가장 새로운 구간이 그려집니다. 구간은 40초 유지된 뒤 20초 동안 사라지므로 작업이 멈춘 지 1분이면 살annel만 남습니다. 두께는 작업이 어디로 갔는지 보여 줍니다. 모델 단계는 제외됩니다. 제외하지 않으면 모든 구간이 Model을 지나기 때문입니다.
- **닳은 살annel.** 역을 많이 쓸수록 살annel이 두껍고 밝아져 세션이 끝날 때 작업 분포를 보여 줍니다.
- **소요 시간.** 호출이 실행되는 동안 역 주위에 두 시계 바늘이 자랍니다. 안쪽은 1분에 한 바퀴, 바깥쪽은 10분에 한 바퀴입니다.
- **백그라운드 작업.** 백그라운드로 보낸 명령, 모니터, 백그라운드 서브에이전트, 워크플로는 그것을 시작한 턴이 끝난 뒤에도 역에 불이 켜져 있고, 작업이 끝되었다고 보고할 때까지 바늘이 자랍니다. 실패한 작업은 빨간 점을 남깁니다. 보고 자체는 사용자의 메시지로 표시되지 않습니다.
- **동시 여러 개.** 함께 시작된 호출은 나란히 날아가고 역에 `×3` 같은 수가 표시됩니다.
- **무엇이 잘못됐는가.** 오류나 거부로 생긴 빨간 점과 횟수는 다음 메시지까지 역에 남습니다.
- **메모리.** 고유 색이 있습니다. 꽉 찬 맥박은 Claude가 요청한 메모리이고, 점선을 따라 오는 빈 맥박은 훅이 먼저 가져온 것입니다. 역 아래에서 평범한 수는전자를, `↓`는후자를 셉니다.
- **컨텍스트 창.** 중심 주위의 고리가 세션이 진행되며 채워지고, 이름 위에 비율이 표시됩니다. 70%에서 호박색, 90%에서 빨간색이 됩니다.
- **모델 변경.** 중심과 Model 역이 몇 초간 울리고 피드에 `opus 5.5 → fable 5.2` 같은 행이 추가됩니다. 같은 폴더의 이전 세션과 다른 모델로 세션이 시작될 때도 같습니다.
- **서브에이전트.** 아직 일하는 각각은 Agents 역 주위를 작은 점으로 돌고, 그 호출은 거기서 시작됩니다.
- **답변.** 답변이 준비되면 중심에서 넓은 고리 하나가 나갑니다.

지도 아래에는 지금 실행 중인 것을 알려 주는 줄과 최근 16개 행(`logRows`가 `fill`이면 데스크톱 패널의 공간에 맞는 만큼)이 있습니다. `●` 실행 중, `·` 완료, `✕` 실패·차단, `◆` 모델 변경입니다. 한 역에서 연달아 끝난 호출은 한 행으로 접히고, 이름에 나온 것 외에 대신하는 두 개를 `+2`로 표시합니다. 실행 중인 호출은 뒤에 온 것에 밀려나지 않고 끝날 때까지 마지막 행으로 남으므로 목록과 지도가 같은 말을 합니다. 그런 행은 목록의 절반을 넘지 않으며, 그보다 많이 실행 중이면 마지막 행에 나머지를 `+22`로 표시합니다.

각 행은 한 줄입니다. 단어는 패널 가장자리에서 잘리고, 시간은 오른쪽 열에 있으며, 시간이 걸리지 않은 것(메시지 도착 등)은 대시로 표시하고 답변 행에는 턴 전체의 길이가 나옵니다. 이름이 긴 행은 시간 앞에 `▸`가 있어 누르면 전체를 읽고 다시 누르면 닫습니다. 한 번에 한 행만 열립니다. 터미널에서는 지금 줄의 오른쪽에 컨텍스트 비율과 모델도 표시됩니다. 그릴 곳이 없기 때문입니다.

### 각 호출이 컨텍스트에 더하는 것

고리는 컨텍스트 창이 얼마나 찼는지만 말하고 무엇이 채웠는지는 말하지 않습니다. `contextCost`가 켜지면 호출 행에 시간 뒤에 그 호출의 답변으로 컨텍스트가 얼마나 늘었는지 대략 표시됩니다. `85 ms +42k`. 지도에서는 각 역의 횟수 줄에 세션의 합계가 더해집니다. `9 · 180k`. 수치는 옆의 것(행에서는 시간, 지도에서는 횟수)과 같은 색을 받으므로 밝은 테마와 어두운 테마 모두에서 읽힙니다.

이것은 추정치입니다. Claude Code가 모드에 마지막 응답이 몇 토큰으로 이루어졌는지 알려 주므로, 모드는 모델 단계 사이에 컨텍스트가 얼마나 늘었는지 보고 그 단계와 함께 온 답변의 호출에 배정합니다. 증가분에는 모델 자신의 말, 훅이 추가한 것, 턴 시작 시 사용자의 메시지도 포함됩니다.

- **한 단계 늦음.** 호출의 수치는 그 호출이 끝날 때가 아니라 다음 단계에 답변이 나왔을 때 표시됩니다. 턴의 마지막 단계에서 만들어진 호출, 중단된 턴이나 압축 전의 호출은 수치를 받지 못하고, 컨텍스트를 줄이는 압축은 어디에도 아무것도 넣지 않습니다.
- **공유.** 한 단계의 호출이 두세 개면 증가분을 균등히 나누고 `~`를 붙입니다. `~+14k`. 한 단계에 호출이 더 많으면 큰 읽기와 짧은 명령에 같은 수치가 붙게 되므로 행에는 넣지 않습니다. 모두 한 역이었다면 그 역의 합계는 전체를 받습니다. 접힌 행은 호출들의 수치를 더하고, 일부에 수치가 없으면 `~`를 붙입니다.
- **메인 루프만.** 서브에이전트는 Claude Code가 보고하지 않는 자체 컨텍스트를 채우므로 그 호출에는 수치가 없습니다. 그 답변이 가져온 증가분은 그것을 시작한 메인 루프 호출에 표시됩니다.

합계는 지도의 모든 그리기에 있습니다. 데스크톱 앱, VS Code, 터미널 그림은 하나의 그리기이고, 브라일 지도는 역의 횟수 뒤에 합계를 이름 색으로, 행 수치의 더하기 기호와 함께 씁니다. `Files 9 +180k`. 행만 보여 주는 터미널에서는 같은 방식으로 횟수 줄에 있습니다.

브라일 지도는 모든 역의 합계를 그리거나 아예 그리지 않습니다. 가장 넓은 합계를 모든 이름 옆에 넣을 공간이 없는 좁은 패널이나 긴 이름·큰 횟수에서는 모두 생략하고 이름은 온전히 유지하며, 행에는 여전히 수치가 있습니다. 영어 이름은 횟수가 10 미만이면 50열부터 맞고, 모든 역의 횟수가 크면 최대 68열이 필요합니다.

## 터미널에서

터미널은 행만 보여 줍니다. `terminalView`가 `picture`이면 그림을 표시하는 터미널(kitty, Ghostty 등)에서 행 위에 지도 그림이 표시되고 데스크톱 앱처럼 움직입니다. Claude Code는 전체 화면으로 그려야 합니다. 패널이 대화 아래에 있다면 Claude Code가 메인 화면에서 그리고 있으므로 행만 남습니다. `/tui fullscreen`을 입력하거나 `CLAUDE_CODE_NO_FLICKER=1 claude`로 시작하세요. tmux 안에서는 `allow-passthrough on`과 `focus-events on`을 설정하세요. 그 밖의 터미널과 24열 미만의 패널은 예전처럼 행만표시합니다.

iTerm2에서는 3.7.8 이상이 필요합니다. 이전 버전은 받은 그림을 탭이 닫힐 때까지 계속 보관합니다. iTerm2 3.7.7에서는 움직이는 지도가 프레임당 약 2MB, 5분에 17GB를 차지했습니다(#81). 그곳에서는 그림이 꺼져 있고 행 위에 그 사실을 알리는 줄이 있습니다. iTerm2를 업데이트하거나 `terminalView`를 `braille`로 설정하세요. 모드는 `TERM_PROGRAM`으로, ssh나 tmux 안에서는 `LC_TERMINAL`로 iTerm2를 알아내고, 버전은 `TERM_PROGRAM_VERSION` 또는 `LC_TERMINAL_VERSION`으로 읽습니다. 버전을 알 수 없으면 그림은 꺼집니다.

모드는 데스크톱 앱과 같은 그리기에서 그림을 직접 페인트하며, 퍼블릭 도메인인 X.Org misc-fixed 비트맵 글꼴의 글자를 씁니다. 출처는 [FONTS.md](FONTS.md)에 있습니다. 지도의 무언가가 움직이는 동안 초당 최대 5프레임으로 그립니다. 중심의 숨쉬임은 무언가 실행 중일 때만 그림에서 일어나며, 지도가 마지막으로 바뀐 뒤 10분은 부드럽게, 그 후에는 5초마다 한 프레임입니다. 멈춰 있으면 흔적이 사라진 뒤 그림은 가만히 있습니다.

`theme`이 `auto`이면 그림은 iTerm2, rxvt, Konsole이 설정하는 터미널의 `COLORFGBG`에 따라 밝거나 어둡습니다. 알려 주는 것이 없으면 어둡고, 밝은 터미널이 알려 주지 않는다면 `theme`을 `light`로 설정하세요. 그림에는 자체 배경이 없어 터미널 배경이 비쳐 보이며, 패널 회색과 조금 다르면 지도 주위에 희미한 상자가 생깁니다. `paneBackground`를 `transparent`로 하면 회색을 없애 지도와 행 뒤로 터미널이 모두 보이고, 터미널이 반투명이어도 같습니다. 터미널 색으로 `#rrggbb`를 주면 패널을 그 색으로 칠합니다. `colors`에 `background=#rrggbb`를 주면 그림에 자체 배경을 둡니다.

터미널은 셀의 높이를 알려 주지 않습니다. `cellShape`가 그것을 지정합니다. 셀이 너비의 몇 배인지로 기본값 2.4는 iTerm2의 Monaco 12이며, kitty의 Menlo는 약 2입니다. 그림 아래에 빈 띠가 생기면 높이고, 오른쪽에 생기면 낮추세요.

### 브라일 점으로 보는 지도

`terminalView`가 `braille`이면 지도가 행 위에 텍스트 셀로 서 있습니다. 살annel과 역·중심은 브라일 점, 이름은 글자입니다. 그림이 필요 없고 브라일 글자가 있는 글꼴만 있으면 되므로 Windows Terminal과 대부분의 Linux 터미널에서 표시됩니다. `picture`가 아무것도 보여 주지 않는 곳에서도 가능합니다. 자동 대체는 아닙니다. 그림을 표시할 수 없는 터미널은 사용자가 직접 `braille`을 고를 때까지 행만 유지합니다.

![Windows Terminal의 브라일 지도](docs/map-braille.png)

같은 판을 같은 방식으로 읽되, 셀이 담을 수 있는 것만 표현합니다.

- **역.** 빈 고리는 아직 사용되지 않았고, 점이 있는 고리는 사용되었으며, 꽉 찬 고리는 지금 작동하며 맥박칩니다. 막 끝난 역은 몇 초간 밝게 남습니다. 빨간색은 오류·거부이고 이름 뒤 `!1`은 다음 메시지까지 그 횟수이며, `x3`은 동시에 실행 중인 호출 수입니다. `contextCost`가 켜지면 모든 역의 합계를 넣을 공간이 있을 때 횟수 뒤에 합계가 옵니다. `Files 9 +180k`.
- **살annel.** 첫 호출로 역의 색을 얻고 많이 쓰면 선이 하나 더 생깁니다. 호출이 시작되면 켜지고 맥박이 나갔다가 끝날 때 돌아옵니다. 훅이 먼저 가져온 것은 역에서 안으로 들어옵니다.
- **중심.** 외곽선이 컨텍스트 창이며 위에서 시계 방향으로 채워집니다. 70%에 호박색, 90%에 빨간색, 이름 위에 비율, 아래에 모델 이름이 있습니다. 모델은 변경 후 몇 초간 밝습니다. 답변이 준비되면 고리가 하나 나갑니다.
- **서브에이전트.** 아직 일하는 각각은 Agents 역 주위를 점으로 돕니다.

셀에는 색 하나와 점 하나만 담을 수 있어 그리지 않는 것:

- 역 사이의 경로와 사라지는 흔적;
- 작동 중인 역 주위의 시계 바늘;
- 역의 아이콘, 점선 외곽선, 중심의 숨쉬임;
- 맥박이 닿는 고리와 모델이 바뀌는 고리;
- 나란한 맥박. 함께 시작된 호출은 하나로 날아가고 `x3`이 수를 말함;
- 훅이 먼저 가져온 것의 두 번째 수 `↓`. 한 수가 둘을 셈;
- 서브에이전트 호출이 Agents 역에서 출발하는 것. 모든 호출은 중심에서 나감;
- 빛의 페이드. 역이 밝았다가 갑자기 꺼짐.

색은 데스크톱 앱과 같은 지도 자체 색입니다. `theme`과 `colors`가 유지되고, `auto`에서는 그림처럼 `COLORFGBG`에 따라 밝거나 어둡고, 알려 주는 것이 없으면 어둡습니다. 밝은 터미널이 알려 주지 않으면 `theme`을 `light`로 설정하세요. `background`의 의미도 같습니다.

- `solid`(기본): 셀은 팔레트의 배경 위에 있고 단어는 그 텍스트 색이므로 어떤 패널에서도 읽힙니다. 패널 바닥은 Claude Code 테마에서 오고 지도는 그것을 물을 수 없으므로, 밝은 터미널에 어두운 테마면 어두운 패널에 밝은 지도가 됩니다.
- `transparent`: 셀에 바닥이 없고 단어는 터미널 자체 색입니다. 터미널과 Claude Code 테마가 일치할 때 선택하세요. 다르면 글자를 거의 읽을 수 없습니다. `paneBackground`도 `transparent`이면 지도와 패널 모두 터미널이 비쳐 보입니다.

`layout`은 고리를 돌립니다. `motion`이 `reduced`이면 아무것도 날아가거나 맥박치거나 돌지 않습니다. 호출이 역과 살annel을 켜고 서브에이전트는 역 옆에 섭니다.

그림처럼 지도는 패널이 대화 옆에 있을 때만 표시됩니다. Claude Code 기본 렌더러에서는 패널이 대화 아래에 있어 지도에 너무 짧으므로 행만 남습니다. `/tui fullscreen`을 입력하거나 `CLAUDE_CODE_NO_FLICKER=1 claude`로 시작하세요. 지도는 패널 본문이 최소 50열 25행이어야 하며 최대 76×21을 차지합니다. 더 작으면 행만 남습니다. 달라 보일 때만 다시 그립니다. 맥박이 날아가거나 서브에이전트가 도는 동안 초당 약 8회, 작동 중인 역이 맥박칠 때마다, 멈춰 있으면 전혀 없습니다. 마지막 변경 후 10분이 지나면 아직 실행 중인 것에 5초마다 한 프레임을 줍니다.

## VS Code에서

VS Code 확장에서는 패널이 짧아 패널 너비로 그린 지도가 맞지 않습니다. 그곳에서만, 그리고 그곳에서만 지금 줄의 끝에 버튼 세 개가 있습니다. **축소**와 **확대**는 지도를 160~400픽셀의 여섯 너비 중 하나로, 또는 패널 너비로 그립니다. **지도 숨기기**는 패널을 그 한 줄로 접고 **지도 보기**는 다시 불러옵니다. 선택은 다음 세션에도 유지됩니다.

## 옵션

설치 시 한 화면에 표시됩니다. 이후에는 터미널에서 `/config` 또는 `claude plugin configure`를 쓰고 세션을 재시작하세요. 아래 네 그룹으로 나옵니다. 모두 기본값이 있어 아무것도 설정하지 않아도 지도가 동작합니다.

### 외형

값의 그림이 있는 페이지: [옵션 외형](docs/options.md).

| 옵션 | 기본값 | 의미 |
| --- | --- | --- |
| `language` | `en` | `en`, `ru`, `es`, `fr`, `de`, `it`, `pt` 중 하나 |
| `coreName` | `CLAUDE` | 가운데 원에 쓰일 글자, 최대 10자 |
| `theme` | `auto` | 지도 색상. `dark`, `light`, 표면에 따라 결정되는 `auto` |
| `background` | `solid` | 지도 자체 배경, 또는 뒤의 패널이 비치는 `transparent`. 이름 주변 테두리는 배경 색을 유지하므로 다른 색조의 표면에서는 희미한 후광처럼 보임 |
| `paneBackground` | `theme` | 패널 자체를 무엇으로 칠할지. `theme`은 Claude Code 자체, `transparent`는 배경화면·흐림까지 포함해 뒤의 터미널을 비침, `#rrggbb`는 불투명 터미널에 맞출 색. 지원하지 않는 표면은 자체 상태 유지. [터미널에서](#in-a-terminal) 참고 |
| `colors` | 없음 | 직접 지정한 색, 각각 `name=#rrggbb`. [나만의 색상](#colours-of-your-own) 참고 |
| `layout` | `you-top` | 지도에서 사용자의 위치. `you-top` 또는 고리를 반 바퀴 돌려 사용자를 아래, 네트워크·브라우저를 위에 두는 `you-bottom` |
| `motion` | `full` | `full` 또는 `reduced`. 날아가거나 퍼지거나 돌지 않음. 호출은 여전히 역을 켜고 살annel을 깜박이며 경로 구간도 생기고 모두 흐려질 뿐. 실행 중인 역의 시계 바늘은 시계처럼 천천히 움직임 |
| `textSize` | `footnote` | 지도 아래 행의 크기. `caption`, `footnote`, `body`. 터미널은 크기가 하나라 무시 |
| `openAtStart` | `true` | 세션 시작 시 패널이 자동으로 열리는지. `false`면 `/lot-map`을 입력할 때까지 닫혀 있지만, 지도는 세션의 첫 호출부터 유지되어 열 때 완전함 |
| `logRows` | `16` | 지도 아래 목록이 보여 주는 행 수. `16` 또는 패널에 남은 공간만큼(최소 16)인 `fill`. 넘는 오래된 행은 아래에서 잘리고 실행 중인 호출 위에는 남음. 데스크톱 도킹 패널 전용이며 터미널·편집기·모바일은 16 유지 |

### 표시 내용

| 옵션 | 기본값 | 의미 |
| --- | --- | --- |
| `hookReasons` | `false` | 훅 거부의 첫 줄을 최대 72자까지 표시. 끄면 어떤 도구가 멈췄는지만 표시 |
| `guardedHooks` | `true` | `lot-map: its classic.PreToolUse hook was skipped` 같은 알림이 나오는 Team·Enterprise 로그인에서 끄세요. 조직 가드가 다섯 이벤트에서 모드를 배제하며, 끄면 모드가 그 이벤트에 훅을 걸지 않습니다. 이때 지도는 Hooks 역, 훅이 추가한 기록, 입력한 슬래시 명령 행, 압축 표시를 잃습니다. 훅이 거부한 호출은 차단이 아닌 실패 호출로 `✕`를 받음 |
| `subagentNames` | `false` | 서브에이전트의 모델 단계가 시작할 때 준 짧은 이름(최대 40자)으로 누구인지 말함. 끄면 서브에이전트라고만 표시 |
| `contextCost` | `false` | 각 행에 호출의 답변으로 컨텍스트가 얼마나 늘었는지 표시하고 지도에 역별 합계를 더함. 한 단계 늦게 표시되는 추정치. [각 호출이 컨텍스트에 더하는 것](#what-each-call-adds-to-the-context) 참고 |
| `contextWindow` | `model` | 고리와 비율이 컨텍스트를 무엇에 대비해 재는지. `model`은 상태 줄처럼 모델의 전체 창, `compaction`은 `autoCompactWindow`로 지정된 것 같은 자동 압축 창(모델보다 작을 때). 없거나 자동 압축이 꺼져 있으면 `compaction`도 `model`과 같음. 창은 세션의 첫 모델 단계, 압축 후, 모델 변경 시 읽음. `guardedHooks`가 꺼져 있으면 압축 후에는 읽지 않음 |

### 메모리와 서버

| 옵션 | 기본값 | 의미 |
| --- | --- | --- |
| `memoryServers` | `memory` | 도구가 Memory를 켜는 MCP 서버 |
| `memoryCommands` | 없음 | Memory를 켜는 셸 명령·스크립트. 이름 자체이거나 `-`, `_`, `.`로 시작하면 일치하므로 `recall`은 `recall-sync.py`도 이름 |
| `memorySubcommands` | 없음 | 지도가 표시할 수 있는 메모리 명령 뒤의 단어, 예: `add`, `search`. 없으면 명령 자체 이름으로 감 |
| `memoryPaths` | 없음 | 파일을 메모리로 만드는 경로 조각 |
| `memoryLabels` | 없음 | 메모리 도구의 짧은 이름, 각각 `tool=name` |
| `serverStations` | 없음 | MCP 서버의 도구를 원하는 역에 배치, 각각 `server=station`. `files`, `shell`, `web`, `browser`, `agents`, `skills`, `you` 중 하나. 행에는 여전히 `server: tool`로 표시. 설정은 모드 자체 라우팅보다 우선. Memory는 `memoryServers`를 유지하며 둘 다 있으면 그것이 우선하고 알 수 없는 역은 무시 |
| `hookRecords` | `false` | 사용자의 훅이 `[#123]` 같은 번호의 메모리 기록을 추가하면 켜세요. 번호만 Memory에 표시. 그 숫자는 메모리 훅이 아니어도 어떤 훅 텍스트에서든 셈 |

### 터미널 전용

| 옵션 | 기본값 | 의미 |
| --- | --- | --- |
| `terminalView` | `text` | 터미널에서 지도의 모양. `text`는 행만, `picture`는 그림을 표시하는 터미널(iTerm2 3.7.8 이상)에서 행 위에 그림, `braille`은 브라일 글자가 있는 터미널에서 행 위에 브라일 지도. [터미널에서](#in-a-terminal) 참고 |
| `cellShape` | `2.4` | 터미널 그림에서 셀이 너비의 몇 배인지. 1.2~4로 그림이 상자를 채우게 함. [터미널에서](#in-a-terminal) 참고 |

예: 러시아어 이름과 나만의 메모리 서버:

```bash
echo '{"language":"ru","memoryServers":"my-memory"}' | claude plugin configure lot-map@lot-map --values-stdin
```

그림을 표시하지 않는 터미널에서 지도 자체:

```bash
echo '{"terminalView":"braille"}' | claude plugin configure lot-map@lot-map --values-stdin
```

Team·Enterprise 로그인에서 건너뛴 훅 알림 없애기:

```bash
echo '{"guardedHooks":"false"}' | claude plugin configure lot-map@lot-map --values-stdin
```

모든 값은 `"false"`, `"2.4"`처럼 문자열로기록하고, 목록은 쉼표로 씁니다.

## 나만의 색상

`colors`는 지도 색을 하나씩 바꿉니다. 하나, 몇 개, 또는 열세 개 모두 지정할 수 있고, 비워 둔 것은 그대로입니다.

```bash
echo '{"theme":"dark","colors":"accent=#7fb4ff,active=#b8d6ff,text=#e6edf7"}' | claude plugin configure lot-map@lot-map --values-stdin
```

| 이름 | 바꾸는 것 |
| --- | --- |
| `background` | 지도의 바닥과 이름 주변 테두리 |

- `#rgb`와 `#rrggbb`만 받습니다. 그 밖이나 다른 이름은 설정되지 않은 것으로 셉니다.
- `theme`이 `auto`여도 직접 지정한 색은 밝은 표면에서도 유지되고 나머지는 전처럼 다시 칠해집니다. 팔레트 전체를 직접 지정한다면 `theme`을 `dark` 또는 `light`로 하세요.
- `background`가 `transparent`여도 여기서는 패널 색을 주세요. 이름 주변 테두리가 그 색을 받고 후광이 사라집니다.

## 표시하는 것과 보관하는 것

모드는 네트워크 요청을 하지 않고, 파일을 읽지 않으며, 프로세스를 실행하지 않고, 모델을 호출하지 않고, 대화에 아무것도 추가하지 않습니다. 행은 세션 동안만 있습니다. 한 페이지 요약은 [개인정보](PRIVACY.md)에 있습니다.

도구 호출을 추적하는 모드로서 모든 호출의 입력 전체(command line과 파일에 기록되는 텍스트 포함)를 전달받습니다. 그곳에서 이름만 가져가며, 그렇게 하는 코드는 `hooks/classify.ts`의 `classify`입니다. 이 저장소에서 추가한 마켓플레이스는 `main`브랜치를 따르므로 업데이트 시 그곳의 내용을 가져옵니다. 중요하다면 업데이트 전에 diff를 읽으세요.

기본적으로 Claude Code에 한 가지, 각 모델 단계 후 컨텍스트 창이 얼마나 찼는지만 묻습니다. `contextCost`가 켜지면 같은 응답에서 토큰 수를 유지해 각 행과 역에 수치를 붙입니다. 그 밖에는 읽지 않습니다. `contextWindow`가 `compaction`이면 컨텍스트가 어떻게 나뉘는지도 세션의 첫 모델 단계와 압축·모델 변경 후에 묻고, 응답에서 자동 압축 창의 크기만 가져갑니다. 세션 사이에는 마지막으로 사용한 모델 이름을 폴더마다 하나 유지해 변경을 표시합니다. 모두 폴더의 전체 경로 아래, Claude Code의 플러그인 저장소에 있습니다.

훅의 동작: 세션 시작, 프롬프트, 턴, 모델 단계, 도구 호출, 스킬, 압축을 듣고, `subagentNames`가 켜지면 서브에이전트 시작도 듣습니다. 설정 훅의 세 이벤트, `PreToolUse`(훅이 호출을 거부했는지 권한을 물었는지 잠깐 멈췄는지 봄), `UserPromptSubmit`, `SessionStart`(훅이 추가한 컨텍스트를 봄)도 듣습니다. 각 훅은 이벤트를 온 그대로 전달하고 반환값도 온 그대로 돌려줍니다. 입력·결과·컨텍스트·권한 판단을 바꾸지 않고 자체 판단도 만들지 않습니다. 유일한 명령 `/lot-map`은 패널을 엽니다.

이름에는 내용이 아니라 이름만 담깁니다.

- 파일: 경로의 마지막 두 부분;
- 웹 주소: 로그인·비밀번호·경로·쿼리를 제외한 호스트만. 두 가지로 읽힐 수 있는 주소는 스킴만;
- 셸 명령·모니터: Claude가 쓴 짧은 설명 또는 명령의 이름. 명령 줄은 절대 아님. 설명은 모델 자체 말이며 있는 그대로 표시;
- 검색: `Grep`, `Glob`은 도구 이름, 웹 검색은 `web search`, 도구 검색은 `loading tools`로 지도의 언어로 표시. 패턴·쿼리는 절대 아님;
- 메모리 호출: 도구 이름과 기록 번호 또는 짧은 식별자. 텍스트·쿼리는 절대 아님;
- 메모리 명령: 그 이름, 그리고 `memorySubcommands`에 나열한 단어일 때만 뒤의 단어;
- 서브에이전트: 시작할 때 준 짧은 설명. `subagentNames`가 켜지면 그 서브에이전트의 모델 단계에도 첫 40자;
- 백그라운드 작업 보고: 작업이 끝났는지 실패했는지. 요약·출력은 절대 아님;
- 훅 거부: 멈춘 도구의 이름. 첫 줄은 `hookReasons`가 켜질 때만 표시됩니다. 거부가 훅이 발견한 내용을 인용할 수 있기 때문입니다.

모든 이름은 그리기 전에 제어 문자가 제거됩니다.

지도의 장애는 도구 호출이나 모델 턴에 절대 닿지 않습니다.

## 개발

```bash
claude plugin test .
claude plugin validate .
```

단어는 `hooks/text.ts`에 있습니다. 새 언어는 거기에 표 하나와 `.claude-plugin/plugin.json`의 `language` 값 하나를 더하면 됩니다.

터미널 그림은 세 파일로 만들어집니다. `hooks/scene.ts`가 `drawMap`의 그리기를 읽고, `hooks/raster.ts`가 페인트하고, `hooks/png.ts`가 터미널용 픽셀을 패킹합니다. 테스트가 모든 그리기를 페인트하고 페인터가 모르는 것이 있으면 실패하므로, 더 많은 SVG가 필요한 그리기 변경은 거기서 먼저 드러납니다. 다른 테스트 `the terminal picture's font has every letter the map writes, in every language`는 새 언어가 `hooks/font.ts`에 추가해야 하는 글자를 이름으로 알려 줍니다. 그 파일 다시 만드는 법은 [FONTS.md](FONTS.md) 참고.

브라일 지도는 `hooks/braille.ts`가 그립니다. 같은 판의 두 번째 그리기로, 역은 `STATIONS`에서, 타이밍은 `hooks/draw.ts`에서 가져옵니다. `hooks/braille.test.tsx`의 테스트가 두 레이아웃에서 모든 역을 지키고, `hooks/lot-map.test.tsx`의 테스트가 모든 언어의 이름을 지킵니다. 지도에 새 것이 생기면 거기에도 그리거나 [브라일 점으로 보는 지도](#the-map-in-braille-dots)의 빠진 것 목록에 추가해야 합니다. `hooks/braille.test.tsx`의 `INVENTORY`에는 첫 그리기가 보여 주는 각 항목이 한 줄씩 있고, 테스트가 두 그리기를 그것에 묶으며, `scripts/check-surface.mjs`가 그 목록을 같은 줄에 묶습니다.

변경을 보내기 전에 [CONTRIBUTING.md](CONTRIBUTING.md)를 읽으세요. 모드가 지키는 것과 각 항목 뒤의 검사는 [PRINCIPLES.md](PRINCIPLES.md)에 있습니다.
